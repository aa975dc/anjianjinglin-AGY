# 自动按键工具 — 使用说明

> 基于 GitHub 开源项目 **`arkhamvm/keypresser`**（MIT 许可）改造而来。
> 核心逻辑（按键发送 `sender`、热键 `hotkeys`、键表 `keys`、窗口工具 `winutil`、
> 录制 `recorder`）**全部复用上游、与上游逐字节一致**；
> 引擎 `engine.py` 因修复"长按住导致系统级卡键"做了**最小增量改动**（详见 §8.6）。
> 界面层重做并补齐了中文。

---

## 一、怎么启动

| 启动方式 | 说明 |
|---|---|
| **双击 `启动KeyPresser.bat`** | **推荐**。简洁中文界面，只有 3 步 |
| 双击 `启动KeyPresser-迷你版.bat` | 迷你浮动窗口，最小占用，可置顶 |
| 双击 `启动KeyPresser-完整版.bat` | 功能完整的原版界面（录制、诊断、配置档案、多种发送模式） |

三个界面**共用同一套核心**（引擎、热键、发送逻辑），按键、间隔等设置也互通。
但**同一时刻只能运行一个**——因为全局热键 F1/F2/F3 只能归属一个进程，
同时开两个会互相抢热键。想换界面，先关掉当前的再启动另一个。

## 二、界面

### 2.1 简洁版（默认）

![简洁版界面](界面预览-简洁版.png)

界面就是一条直线流程，从上往下做三步，然后按 F1：

```
第 1 步 · 设置要按的键     →  填按键，或点「按下要按的键…」直接按一下
第 2 步 · 设置按键间隔     →  填「按住」和「等待」两个毫秒数
第 3 步 · 循环方式         →  一直循环，或指定循环次数
目标窗口（可选）           →  不选 = 发给当前活动窗口
[启动 (F1)] [暂停 (F2)] [停止 (F3)] [最小化]  →  状态显示在下方
（点「启动」= 3 秒待命倒计时，结束时自动把焦点交还给上一个前台窗口）
```

**最简用法**：点「按下要按的键…」→ 按下你要连按的键 → 填间隔 → 切到目标窗口 → 按 **F1**。

> 点「启动」**按钮**也是安全的：它会先进入 **3 秒待命倒计时**，倒计时结束时
> 自动把焦点交还给上一个前台窗口，然后再开始发送按键（这正是为了修掉"点了按钮
> 焦点落在本工具自己身上、按键发进自己窗口"的老毛病）。
> 想零等待、最稳妥，仍推荐在目标窗口里按 **F1**（焦点本来就对）。

### 2.2 迷你版

![迷你版界面](界面预览-迷你版.png)

一个 **330×307 的独立浮动小窗口**，只留四样东西：

```
按键  [space      ] [按下要按的键]
      已识别：space（扫描码 39）
间隔  [1090   ] 毫秒
      按住 90 + 等待 1000 毫秒
循环  [10     ] 次   ☑ 无限循环

[启动 F1]  [暂停 F2]  [停止 F3]
已停止                        ☑ 窗口置顶
[最小化] [隐藏到后台] [打开日志] [退出程序]
（最后一条提示信息压成一行显示在这里）
关闭窗口只是隐藏，脚本仍在后台运行（F4 可重新显示）
```

**停在屏幕左上角**，尺寸 330×307（客户区），独立窗口。

设计上的三个取舍：

| 取舍 | 说明 |
|---|---|
| **间隔只填一个数** | 内部固定「按住 90 毫秒」，剩下的算「等待」。界面会把这笔拆分**明写出来**（`按住 90 + 等待 910 毫秒`），不做隐藏 |
| **默认窗口置顶** | 它是浮在其他窗口上的小控制面板，方便边干活边看状态；不想要就取消勾选 |
| **没有目标窗口下拉框** | 按键发送给当前活动窗口。先用鼠标把焦点点到目标窗口，再按 F1 即可 |

### 2.3 关掉窗口 ≠ 停止脚本（重要）

迷你版是"关掉也不影响后台运行"的设计：

| 操作 | 效果 |
|---|---|
| **点窗口右上角的 ✕** | **只隐藏窗口**。脚本继续在后台跑，按键照常发送 |
| 点「隐藏到后台」按钮 | 同上（和 ✕ 等价，只是更显眼） |
| **按 F4**（任意时刻） | **显示 / 隐藏窗口**。隐藏后靠它把窗口叫回来 |
| 点「退出程序」按钮 | **真正退出**：停止脚本 + 释放热键 + 关闭程序 |

原理：脚本跑在**独立线程**里，跟窗口是否可见完全无关，所以隐藏窗口不影响它。
但这也意味着**关掉窗口不会停脚本**——想彻底停下并退出，请点「退出程序」。

> 隐藏后如果忘了，可以在任务栏找不到窗口时直接按 **F4** 呼出。

其他行为：
- **自动记住位置**：下次启动回到上次所在的位置；首次运行停在**屏幕左上角**（20, 20）。
- **只显示最后一条消息**：不放日志框以节省空间，但「找不到窗口」「输入被拦截」这类错误仍会显示出来，
  并且**全部写入日志文件**（见第七节）。
- **权限检查改用前台窗口**：因为你是在目标窗口里按 F1，所以迷你版会检查**当前前台窗口**的权限，
  发现对方以管理员身份运行时会提示并询问是否提权重启。

## 三、热键与按键触发逻辑的配合关系

### 3.1 热键绑定

| 热键 | 内部动作 | 调用方法 | 语义 | 可用界面 |
|---|---|---|---|---|
| **F1** | `run_toggle` | `start_script()` | **启动**。已在运行则忽略（幂等） | 全部 |
| **F2** | `pause` | `toggle_pause()` | **暂停 / 继续**（按一次暂停，再按继续） | 全部 |
| **F3** | `stop` | `stop_script()` | **停止**，并强制释放所有仍按住的键 | 全部 |
| **F4** | `minimize`（简洁版/完整版）/ `toggle_window`（迷你版） | `iconify()` / `toggle_window()` | 简洁版/完整版：**一键最小化窗口**；迷你版：**显示 / 隐藏窗口** | 全部 |
| F9 | `record_toggle` | 仅完整版可用 | 录制开/关 | 完整版 |

> F4 在简洁版/完整版是"一键最小化"（不用把鼠标移到标题栏去点 `—`）；
> 在迷你版保留"显示 / 隐藏窗口"的语义——因为迷你版"关掉窗口"只是隐藏，
> 必须有这个热键能把窗口叫回来。

### 3.2 协同关系

```
   [空闲] ──── F1 ───► [运行中] ──── F3 ──► [空闲]
                          ↕
                      F2 暂停/继续
                    （F3 随时可直接停）
```

- **F1 只负责启动**。上游原版是"启动/停止切换"（再按一次会停），我改成了纯启动，
  避免按 F1 想启动却反而停掉；停止统一交给 F3。
- **F2 是暂停而非停止**：播放线程仍在，只是卡在 `_wait_resume()` 等待；
  按 F2 立刻从断点继续，**不会重置循环计数**。
- **F3 是硬停止**：置位 `_stop` 事件，播放线程在 **10 毫秒内**退出（实测，
  前提是线程正处于等待 / 间隔阶段）。**按住（hold）期间**：修复后保持阶段改为
  可中断的分片等待（10 毫秒一片），F3 最多等一个分片即可生效，不再等满整个 hold；
  退出前还会调用 `engine.force_release()` 强制松开所有已按下的键，防止按键卡在系统里。
- 三者互不依赖：任何时刻按 F3 都能停；空闲时按 F2、运行中按 F1 都是安全的空操作。

### 3.3 完整调用链路

```
用户按 F1/F2/F3
   ↓
hotkeys.py   独立线程：RegisterHotKey + GetMessageW 消息循环
   ↓  得到动作名，put 进线程安全队列 queue
gui_simple.py  _poll()  主线程每 50ms 轮询队列
   ↓
_handle_action()  动作分发中枢
   ↓
engine.py    start() / toggle_pause() / stop()  播放线程
   ↓
sender.py    SendInput(物理扫描码) → 目标窗口
```

**为什么要绕队列？** tkinter 不是线程安全的。热键在子线程触发，不能直接改界面控件；
统一投递到队列、由主线程消费，界面才不会崩。

## 四、按键的触发间隔怎么算（重要）

界面上的间隔是**两个值相加**，不是单一数字：

| 字段 | 含义 | 建议值 |
|---|---|---|
| **按住** | 键按下去保持多久 | `90` 毫秒 |
| **等待** | 这一下按完后停顿多久 | 按你的需求填 |

**实际触发间隔 = 按住 + 等待**，界面上会实时显示这个计算结果。

> 最容易踩的坑：想每 1 秒按一次，只把「等待」填 1000 是不够的，
> 真实间隔会是 90 + 1000 = **1090 毫秒**。想精确 1000，就把两个数凑成 1000。

**其他要点**
- 目标程序通常每帧才轮询一次键盘，**「按住」低于 80 毫秒可能被吞掉**，建议 80–120。
- 所有数值框都能**手动直接输入**，也支持上下箭头微调。
- 需要随机抖动来避开反挂机检测时，用完整版里的「随机浮动幅度(%)」。
- **迷你版只让你填一个总数**，内部固定按住 90 毫秒、其余算等待；
  所以迷你版填 1000 就是真的 1000 毫秒一轮，不存在上面那个坑。
  边界处理：总数小于 90 时，按住 = 总数、等待 = 0（50 → 按住 50 + 等待 0）。

## 五、支持的按键写法

在「按键」框里可以直接输入：

| 写法 | 含义 |
|---|---|
| `space`、`enter`、`a`、`f5`、`num7`、`left` | 按名字 |
| `ctrl+c`、`alt+space`、`ctrl+shift+f1` | 组合键（修饰键会被按住） |
| `sc:0x11` | 原始扫描码 |
| `vk:0x41` | 原始虚拟键码 |
| `mouse_left`、`mouse_right`、`mouse_middle` | 鼠标按键 |

不确定名字就点「按下要按的键…」直接按一下，会自动填入。

> 按键以**物理扫描码**发送，因此不受键盘布局影响：步骤里的 `w` 永远是同一个物理键。
> 这一点让它在 DirectInput / RawInput 类程序里也能生效（很多脚本库做不到）。

## 七、日志与问题排查

**日志文件**：`%APPDATA%\KeyPresser\logs\keypresser.log`
（完整路径 `C:\Users\<你的用户名>\AppData\Roaming\KeyPresser\logs\keypresser.log`）

- 单文件上限 **1 MB**，保留 **5 份**轮转（`keypresser.log.1` … `.5`），不会无限涨
- **UTF-8 编码**，中文不乱码
- 每行带**毫秒时间戳 + 级别 + 模块名**

实际内容长这样：

```
2026-09-25 00:33:19.210 [INFO ] keypresser.main 启动 界面模式=mini  参数=['mini']
2026-09-25 00:33:19.265 [INFO ] keypresser.main 系统=Windows-10-10.0.19045-SP0
2026-09-25 00:33:19.375 [INFO ] keypresser.ui   热键注册: 成功={'run_toggle': 'f1', ...} 失败=无
2026-09-25 00:33:20.383 [INFO ] keypresser.ui   热键动作: toggle_window
2026-09-25 00:33:20.385 [INFO ] keypresser.ui   窗口已隐藏到后台（脚本运行中=False），按 F4 可重新显示
```

**怎么打开**：迷你版上点 **「打开日志」** 按钮，直接弹出日志目录。

**记录了哪些东西**（按排查问题的顺序）：

| 类别 | 具体内容 |
|---|---|
| 启动环境 | 界面模式、命令行参数、程序版本、Python 版本、系统版本、工作目录、日志路径 |
| 热键 | 每个热键的注册结果；被其他程序占用时会写明哪个动作失败 |
| 用户动作 | 每次 F1/F2/F3/F4 和按钮点击，以及**被忽略的原因**（如"已在运行"、"未在运行"） |
| 引擎事件 | 启动参数（按键 / 按住 / 等待 / 循环 / 目标窗口）、状态变化、窗口等待、发送失败 |
| 权限 | 目标窗口与自身的完整性级别对比；判定会被 Windows 拦截时记 WARNING |
| 错误 | 按键解析失败、数值非法、配置文件读写失败、引擎报错 |
| **异常** | **未捕获异常**与 **Tk 回调异常**都带完整堆栈 |
| 窗口 | 位置、尺寸、置顶开关、隐藏 / 显示、退出 |

> 最后两条特别重要：GUI 程序没有控制台，tkinter 回调里的异常默认只打印到 stderr，
> 等于被彻底吞掉。现在会被完整记进日志，不会再出现"程序莫名不动了但一点线索都没有"的情况。

## 八、为满足"全中文 + 简洁"所做的改动

### 8.1 全中文

上游只有**英文和俄文**两种语言包，没有中文。我补齐了 **203 条中文文案**，
EN / ZH / RU 三个语言包的 **key 集合与占位符完全一致**（自检会逐一校验），
并把默认语言改为 `zh`。
现在简洁版和完整版界面**都已是全中文**。

另外修掉一处字形缺陷：暂停按钮原先用的 `⏸`（U+23F8）在"微软雅黑"里缺字，
会显示成方框，已换成 `‖`。

### 8.2 简洁界面

新增 `gui_simple.py`，把上游 1224 行的密集界面**替换成一条三步直线流程**：
只保留「按键 → 间隔 → 循环 → 启停」，隐藏录制、诊断、配置档案、发送模式、
步骤编辑器、抖动、启动延时等全部进阶选项。进阶功能仍可在完整版里使用。

**关键取舍**：简洁版**没有重写核心逻辑**，`sender` / `hotkeys` / `keys` / `winutil`
四个模块一个字节都没动；`engine.py` 仅因修复卡键做了最小增量改动（见 §8.6），
其余只是换了个展示层。

### 8.3 迷你界面

新增 `gui_mini.py`，但**它是继承简洁版做出来的**，只覆盖 `_build_ui` 和
`_target_title` / `_elevation_hwnd` / `_sync_buttons` / `log` / `refresh_windows`
这几个方法。所以引擎接线、热键管理、队列轮询、配置存档**全部共用一份代码**，
不存在两套实现分叉的风险。

为此在 `gui_simple.py` 里加了 **5 个薄扩展点**：
- `TITLE` 类属性（让子类能改窗口标题）
- `_hotkey_bindings()` 钩子（让子类能追加 / 覆盖自己的热键）
- `_hotkey_label()` 钩子（让子类能给新热键取中文名）
- `_extra_settings()` 钩子（让子类能追加自己的存档字段）
- `_elevation_hwnd()` 钩子（让子类能换一个窗口做权限对比）

这五处都是**加法**，没有改动简洁版自身的任何行为。

### 8.4 迷你版：关掉窗口不影响后台运行

需求是"关掉但不影响后台运行"，落地方式：

| 机制 | 实现 |
|---|---|
| 点 ✕ 只隐藏 | `MiniApp.__init__` 里把 `WM_DELETE_WINDOW` 从父类的"真正退出"改成 `hide_window`，`on_close` 保持原语义（真退出） |
| 隐藏后能叫回来 | 迷你版的热键表多一项 `toggle_window: f4`，走 `_hotkey_bindings()` 钩子覆盖 |
| 后台确实照跑 | 脚本在 `engine` 的独立线程里，与窗口可见性无关；隐藏不影响线程 |

## 十、注意事项

1. **按键发送给"当前活动窗口"**。要么先把焦点点到目标窗口再按 F1，
   要么在简洁版/完整版的「目标窗口」里选好它（完整版还有「3 秒后抓取当前窗口」适配全屏程序）。
   **迷你版没有目标窗口下拉框**，一律发给当前活动窗口，所以一定要「在目标窗口里按 F1」。
2. **启动方式**：**只有简洁版**点「启动」按钮会先进入 **3 秒待命倒计时**，倒计时结束时
   自动把焦点交还给上一个前台窗口再开始，所以点按钮已经安全；**迷你版与完整版**点按钮
   是**即时启动**（不倒计时）。在目标窗口里按 **F1** 仍是零等待、最稳的方式（焦点本来
   就对），且 F1 在**所有界面**都不倒数。
3. **目标程序以管理员运行时，本工具也必须以管理员运行**
   （用 `KeyPresser\run_admin.bat`），否则 Windows 会静默丢弃模拟按键。
   简洁版按所选目标窗口判断、迷你版按当前前台窗口判断，都会提示并询问是否提权重启。
4. **迷你版点 ✕ 不会退出程序**，只是隐藏窗口、脚本继续在后台跑。
   要彻底关掉请点窗口里的 **「退出程序」**，或先按 F4 把窗口叫出来再退出。
   这是"关掉不影响后台运行"的刻意设计，别误以为程序已经关了。
5. **同一时刻只能运行一个界面**（全局热键只能归一个进程）。换界面请先关掉当前的。
6. **F1 是 Windows 通用帮助键**，部分软件会用它。若冲突，可在完整版的
   「热键」区域改绑成别的键。F4 在个别软件里也有用途，同理。
7. **遇到问题先看日志**：`%APPDATA%\KeyPresser\logs\keypresser.log`，
   迷你版点「打开日志」即可。里面记录了启动环境、热键注册结果、每次动作、
   窗口等待、权限对比和完整异常堆栈。
8. 本工具只调用 Windows **公开输入 API**，不读写游戏内存、不注入进程、
   也无法绕过反作弊。自动化操作在线程序可能违反其用户协议，请自行评估。

说明：
