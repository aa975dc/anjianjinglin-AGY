# KeyPresser

**[Скачать KeyPresser.exe](https://github.com/arkhamvm/keypresser/releases/latest)** — Windows, переносимый, без установки.

[English documentation](README.md)

Автонажиматель клавиш для окна игры: список шагов в нужной очерёдности, время
удержания и пауза после каждого шага, циклы, запись живых нажатий и настраиваемые
глобальные хоткеи. GUI на tkinter, зависимостей нет — только Python 3.13 и WinAPI.

## Запуск

Готовый exe (ничего ставить не нужно):

```bash
C:\Users\Arkham\claude\keypresser\dist\KeyPresser.exe
```

Из исходников: `run.bat`, а `run_admin.bat` — то же с правами администратора.
Для exe права администратора даёт ПКМ → «Запуск от имени администратора».
Это нужно, если сама игра запущена от администратора: Windows не даёт процессу
с меньшими правами отправлять ввод в окно процесса с большими (нажатия просто
исчезают).

## Язык интерфейса

По умолчанию английский. Переключается на ходу — комбобокс «Language» в правом
верхнем углу или меню `Language`; выбор сохраняется в настройках и в профиле.
Строки живут в `i18n.py`: новый язык — это ещё один словарь в `CATALOG` и строка
в `LANGUAGES`, менять код GUI не нужно.

## Сборка exe

```bash
C:\Users\Arkham\claude\keypresser\build.bat
```

Нужен PyInstaller (`python -m pip install pyinstaller`). На выходе —
`dist\KeyPresser.exe`, один переносимый файл ~11 МБ, консоли нет, иконка
генерируется скриптом `make_icon.py` (без сторонних библиотек).

* `--onefile` распаковывается при каждом старте (~1 с). Нужен мгновенный запуск —
  заменить на `--onedir` в `build.bat` и носить папку `dist\KeyPresser` целиком.
* Профили exe ищет и сохраняет в папке `profiles` **рядом с самим exe**,
  настройки сеанса — в `%APPDATA%\KeyPresser\settings.json`.

## Как кодируются клавиши

Клавиша задаётся **физическим скан-кодом** (PS/2 set 1) и уходит через
`SendInput`, а не как символ. Поэтому:

* русская раскладка ни на что не влияет — шаг `w` всегда нажимает ту же
  физическую клавишу, на которой написано «ц»;
* игры на DirectInput/RawInput (которые не видят ввод от `keybd_event` и
  большинства python-библиотек) нажатие получают.

В списке шагов рядом с именем показано, что реально уйдёт в игру:
`w [sc 11 / ц]` — имя, скан-код, буква той же клавиши в ЙЦУКЕН.
Суффикс `e` у кода (`ralt [sc 38e]`) — extended-клавиша (префикс E0).

Форматы записи клавиши в поле «Клавиша»:

| Запись | Что это |
|---|---|
| `space`, `alt`, `ralt`, `f5`, `num7`, `left` | по имени |
| `alt+space`, `ctrl+shift+f1` | комбинация: модификаторы зажимаются, потом клавиша |
| `sc:0x11` / `sc:17` | напрямую скан-код |
| `sc:e0:0x35` | скан-код с префиксом E0 (extended) |
| `vk:0x41` | напрямую virtual-key код |
| `mouse_left`, `mouse_right`, `mouse_middle` | кнопки мыши |

Модификаторы: `ctrl`, `shift`, `alt` (= левые), плюс явные `lalt`, `ralt`,
`lctrl`, `rctrl`, `lshift`, `rshift`, `lwin`.

**Одиночный модификатор** (нужен только `lalt` и ничего больше) — в диалоге
«Записать клавишу» нажмите и **отпустите** его: комбинация фиксируется по
отпусканию, поэтому `lalt` записывается сам по себе. Если модификатор при этом
удерживать и нажать другую клавишу, получится комбинация. То же можно набрать
руками в поле «Клавиша»: `lalt`.

Для хоткеев одиночный модификатор не годится — `RegisterHotKey` требует обычную
клавишу, поэтому диалог хоткея ждёт её (`ctrl+alt+f6` — можно, просто `alt` — нет).

## Хоткеи (настраиваются в GUI, работают внутри игры)

| По умолчанию | Действие |
|---|---|
| `F6` | запуск / остановка скрипта |
| `F7` | пауза / продолжить |
| `F8` | аварийный стоп (и скрипта, и записи) |
| `F9` | запись: старт / стоп |

Кнопка «Задать» ловит нажатие физически, комбинации вида `ctrl+alt+f6` тоже
годятся. Если хоткей занят другой программой — в журнале появится сообщение,
и это действие останется без хоткея.

## Запись нажатий

«Начать запись» (F9) ставит низкоуровневый хук клавиатуры и мыши и пишет реальные
нажатия вместе с паузами: время удержания клавиши → `hold_ms`, зазор до
следующего нажатия → `delay_ms`. Зажатый модификатор вокруг другой клавиши
склеивается в комбинацию (`ctrl+c` — один шаг), одиночное нажатие модификатора
остаётся отдельным шагом. Свой собственный ввод и сами хоткеи в запись не
попадают. Галочка «заменять последовательность» решает, затирать список или
дописывать в конец.

## Особенности Alt

* Одиночное нажатие `alt` в обычном оконном приложении открывает системное меню
  окна — окно «замирает», пока меню активно. В играх этого обычно нет, но если
  цель — обычная программа, лучше использовать `alt` как модификатор
  (`alt+space` и т.п.), а не отдельный шаг.
* `ralt` Windows сопровождает фантомным нажатием левого Ctrl (наследие AltGr).
  При записи такой Ctrl автоматически выбрасывается, чтобы не появлялся лишний
  шаг; при воспроизведении `ralt` отправляется как есть.

## Шаг

| Поле | Смысл |
|---|---|
| Клавиша | что нажать (см. форматы выше) |
| Действие | `нажать` (down+up), `зажать` (только down), `отпустить` (только up) |
| Удерж., мс | сколько держать клавишу нажатой |
| Пауза после, мс | пауза до следующего шага |
| Повтор | сколько раз повторить именно этот шаг |
| Вкл | выключенные шаги пропускаются (двойной клик по строке) |

«Зажать» + «отпустить» — для длительного удержания (например, зажать `w`,
сделать другие шаги, потом отпустить). При остановке всё зажатое отпускается
принудительно, так что клавиша не залипнет.

Правка любого поля применяется к выбранному шагу сразу — строка списка
обновляется по мере ввода, поэтому значение не может остаться «висеть» в
редакторе неприменённым. Кнопка «Применить к выбранному» осталась для тех,
кому нужно явное действие. На уже запущенный прогон правки не влияют: он
работает с тем набором шагов, с которым стартовал.

## Цикл

* **Повторов цикла** — 0 значит бесконечно, до F6/F8.
* **Пауза между циклами**.
* **Случайный разброс задержек, %** — ±% к каждой паузе и удержанию, чтобы
  интервалы не были идеально ровными.
* **Задержка перед стартом** — время переключиться в игру после F6.

## Режимы отправки

1. **Только когда окно игры активно** (по умолчанию, безопасно) — если окно
   потеряло фокус, скрипт встаёт на ожидание и не жмёт клавиши в чужие окна.
2. **Активировать окно и жать** — сам поднимает окно игры на передний план.
3. **В фоне, PostMessage** — отправка сообщений прямо в окно, можно работать
   в другом окне. Многие игры это игнорируют — проверять на своей игре.

Целевое окно выбирается из списка; для полноэкранных игр удобнее кнопка
«Взять активное через 3 с»: окно свернётся, вы переключитесь в игру, и она
подхватит активное окно. Собственное окно KeyPresser в список не попадает.

Окна, у которых прав больше, чем у KeyPresser, помечены в списке как **`[АДМИН]`**
(читается уровень целостности процесса окна). Стоит выбрать такое окно — сразу
появится предложение перезапустить KeyPresser от администратора: настройки и
последовательность сохраняются, новый процесс поднимается через UAC, старый
закрывается. Если отказать в UAC, приложение продолжит работать как было и
скажет в журнале, что нажатия в это окно Windows будет блокировать. Попытка
нажать «Старт» с такой целью тоже упирается в это предложение — запускать
впустую бессмысленно.

## Профили

`Профиль → Сохранить как...` пишет JSON в `keypresser/profiles/`. Пример:
`profiles/example.json`. Настройки последнего сеанса сохраняются автоматически
в `%APPDATA%\KeyPresser\settings.json`.

## Файлы

| Файл | Ответственность |
|---|---|
| `main.py` | точка входа, DPI-awareness |
| `gui.py` | окно, список шагов, редактор, журнал, профили |
| `engine.py` | рабочий поток воспроизведения, циклы, паузы, jitter |
| `recorder.py` | запись нажатий (`WH_KEYBOARD_LL` / `WH_MOUSE_LL`) → шаги |
| `sender.py` | `SendInput` со скан-кодами + режим `PostMessage` |
| `hotkeys.py` | глобальные хоткеи (`RegisterHotKey` + цикл сообщений) |
| `keys.py` | таблица VK/скан-кодов, разбор комбинаций, ЙЦУКЕН-подсказки |
| `winutil.py` | список окон, поиск, активация, проверка фокуса |
| `profiles.py` | JSON-профили, валидация, настройки сеанса |
| `i18n.py` | словари EN/RU, `t()` с откатом на английский |
| `make_icon.py` | генерация `icon.ico` (16/24/32/48) без сторонних библиотек |
| `build.bat` | сборка `dist\KeyPresser.exe` через PyInstaller |

## Если нажатия не доходят

Сначала два встроенных инструмента — они отвечают на вопрос «кто виноват»
без догадок:

* **«Диагностика (через 3 с)»** — переключитесь в игру, через 3 секунды в журнал
  ляжет отчёт: своё имя и уровень целостности, активное окно с процессом,
  доступен ли процесс игры (недоступен = игра выше по правам), совпадает ли
  активное окно с целью, результат тестового `SendInput` и итоговый вывод.
* **«Проверка отправки»** — прогоняет последовательность в собственное окно
  KeyPresser и показывает, что дошло. Дошло — отправка работает, дело в игре.
  Не дошло — дело в правах или блокировке ввода. Если фокус ушёл, проверка
  сама останавливается и не сыплет нажатия в чужое окно.

Дальше по частоте:

1. **Нажатия уходят не в игру.** Кнопка «Старт» мышью оставляет активным окно
   KeyPresser — и все нажатия достаются ему же. Правильно: выбрать целевое окно
   и жать хоткей `F6` **находясь в игре**, либо включить режим «Активировать
   окно и жать».
2. **Две копии KeyPresser запретить нельзя — они уже запрещены.** Вторая копия
   не запускается: показывает сообщение и выводит на передний план окно первой.
   Проверка идёт по двум признакам — именованный мьютекс и уже открытое окно
   `KeyPresser`. Раньше вторая копия молча забирала себе `F6`.
3. **Игра запущена от администратора**, а KeyPresser нет → `SendInput` отвечает
   кодом 5, приложение показывает это отдельным окном. Лечится запуском
   от администратора (`run_admin.bat` рядом с exe или ПКМ по exe).

   Частый случай: **Steam запущен от администратора** — игра наследует его токен
   и тоже получает `high integrity`, хотя вы её «просто из Steam запустили».
   Диагностика читает уровень целостности процесса игры и говорит об этом прямо
   (`Права: процесс игры high, KeyPresser medium`). Судить по «процесс
   недоступен» нельзя: запрос `PROCESS_QUERY_LIMITED_INFORMATION` к процессу
   того же пользователя удаётся и для повышенного процесса.

   Альтернатива запуску от администратора — снять галку «Запускать от имени
   администратора» в свойствах `steam.exe`: тогда ни Steam, ни игре повышенные
   права не нужны, и KeyPresser хватит обычного запуска.
4. **Игре не хватает длительности нажатия** → «Удерж., мс» 80–120.
5. **Античит фильтрует синтетический ввод** — не лечится настройками.
6. Режим PostMessage игра может просто игнорировать — используйте режимы
   с активным окном.
